# The TypeScript client: design

Why `@agneta/client` is built the way it is. What it does is in [README.md](README.md); the wire contract it implements is [docs/APP_PROTOCOL.md](../../docs/APP_PROTOCOL.md).

## What it's for

Every app that talks to Agneta used to write the same hundred careful lines: open the WebSocket, tell "Agneta isn't running" from "the connection dropped", offer to open Agneta, pair or initialize with a kept token, forget a token Agneta no longer accepts, follow `agneta/accessChanged`, wait out an engine download, route `session/update` to the right session, answer permission requests, and turn error codes into something to show. Project Chat and Replica Bench each carried a copy (`acp.mjs`, `chat.mjs`, `agneta.mjs`). The library is that code, once, typed and tested, with nothing of the protocol hidden; both examples now run on it.

## Research, in short

- **The protocol** was read in full (APP_PROTOCOL.md, README's developer guide, DIAGNOSTICS.md) and checked against the router (`Router+Apps.swift`, `Router+Sessions.swift`, `Router+Turns.swift`, `AccessReport.swift`, `GrantScope.swift`, `SessionPolicy.swift`). What the code says and the docs leave implicit:
  - an app may call exactly `agneta/catalog`, `agneta/setup`, `agneta/pair`, `initialize`, `agneta/access`, `session/new`, `session/load`, `agneta/fork`, `agneta/trace/read`, and on a session `session/prompt`, `session/close`, `session/set_mode`, `session/set_config_option`, `session/set_model`, `agneta/steer`, `agneta/instructions/set`; the only notification it may send is `session/cancel`;
  - Agneta sends `agneta/pairingCode`, `agneta/catalogChanged`, `agneta/accessChanged`, `agneta/queued`, `agneta/sessionStopped` (`user`, `engine`, `limit`), `agneta/rateLimited`, `agneta/trace` and `session/update`, and one request, `session/request_permission`;
  - every refusal of a policy, scope or tool server is `-32602` with `data.agneta.unenforceable: [field]` and `data.agneta.reason`; an engine refused for access is `-32602` with `data.agneta.access`; a session that opened while access changed, `data.agneta.accessChanged: true`; a saved task whose engine stores sessions differently now, `data.agneta.stateChanged`;
  - `needsSignIn` and `rateLimited` keep the engine's own code and add data, so they must be recognised by data before code;
  - a WebSocket upgrade with any `Origin` header is refused. Browsers and Electron renderers always send one, so the library runs in Node (22 or later, which has `WebSocket` built in) and Electron's main process, and says so rather than failing as "not running".
- **The apps.** `examples/project-chat` (`acp.mjs`, `chat.mjs`, `main.mjs` with `safeStorage`) and `examples/replica-bench` (`acp.mjs`, `agneta.mjs`, `test/stand-in.mjs`), plus the Swift `AppClient` in `RouterIntegrationTests.swift` and `Sources/agneta-testclient`. Things they got right and the library keeps: a request timeout that rejects one call, a pairing timeout longer than Agneta's 5-minute window, a quiet connect that never opens the approval window, a reconnect after a drop to learn whether access was removed, and the `-32015` retry loop. Things the library improves: a timeout no longer closes the whole connection, updates that arrive before `session/new` answers aren't lost, and "not running" is told apart from "Agneta refused this connection".
- **ACP's own SDK** (`@agentclientprotocol/sdk`, 2.8.0 when this was written) was considered and not used. It's built for stdio agents and clients, needs `zod` and an MCP server package as peers, weighs about 5 MB unpacked, and has had a release every few days (2.2 to 2.8 in three weeks). Agneta's app surface is a fixed, small set of methods over a WebSocket, which the SDK doesn't provide as a transport, and the repo keeps to very established dependencies. So the library has **no runtime dependencies**. Its ACP types (`src/acp.ts`) were written from ACP's published v1 schema, limited to what Agneta passes through, and keep `_meta` open.

## Decisions

**Location and name.** `clients/typescript/`, apart from `examples/`: a client is a product, published and versioned on its own, while the examples are apps that use it. `clients/` is for every official client: another language's goes beside this one (`clients/swift/`, `clients/python/`), each with its own workflows and tags named after it, as this one's are: `client-typescript.yml` (build and test), `client-typescript-release.yml` (publish), and tags `client-typescript-v<version>`. Agneta's own `v*` tags and `release.yml` stay the app's. The npm name is **`@agneta/client`**: `agneta`, `@agneta/client`, `agneta-client` and `agneta-sdk` were all free on npm when checked (2026-11-19). A scope keeps room for more packages (a tool-server helper could be `@agneta/tools`) and makes the official one unmistakable. It needs the npm organization `agneta`, which the maintainer creates. If it can't be had, `agneta-client` is the fallback.

**Module format.** ESM only, compiled by `tsc` to ES2022 with declaration files and source maps; `exports` has `.` (everything that runs anywhere there's a `WebSocket`) and `./node` (file and Keychain token stores, opening Agneta with `open`, probing a port), so the core never imports `node:` modules. `"engines": {"node": ">=22"}`. CommonJS callers use `import()`; Electron's main process loads ESM.

**Two layers, one object graph.**

- `Connection` is JSON-RPC 2.0 over one WebSocket: `request`, `notify`, handlers for notifications and incoming requests, a tap on every frame in both directions, and typed overloads for every Agneta method with a string fallback. Anything Agneta offers, now or later, is reachable through it.
- `AgnetaClient` → `Session` → `Turn` is the high level. The client connects, pairs, initializes, keeps the access report current and routes notifications; a session wraps one task; a turn is one prompt. `client.connection` is the raw layer of the same connection, so an app can mix them (send a raw request, then keep using the session).

**Streaming.** A `Turn` is both a promise of its result (`await turn`) and an async iterable of its events (`for await (const event of turn)`), discriminated by `type`: `update` (ACP's `session/update`, itself discriminated by `sessionUpdate`), `queued` and `rateLimited`. Events are buffered from the moment the prompt is sent, so iterating late misses nothing, and every iterator gets every event. Sessions and the client also emit events (`on(name, listener)` returns an unsubscribe function) for apps that prefer callbacks. The emitter is the library's own (a few lines), not `node:events`, to keep the core free of Node.

**Tokens.** A `TokenStore` is `load`, `save`, `clear`, sync or async. `memoryTokenStore()` keeps nothing past the process; `fileTokenStore(path)` writes a mode-0600 file; `safeStorageTokenStore(safeStorage, path)` encrypts with Electron's `safeStorage` (its key is in the login Keychain), taking the `safeStorage` object as a parameter so the library never imports Electron. The client saves only `remembered: true` tokens, clears one Agneta answers `-32001` to, and keeps an Allow Once token in memory for the connection only. One store per Agneta build: the docs and examples key the file by port.

**Errors.** Every failure is an `AgnetaError` subclass with a literal `kind`, so both `instanceof` and `switch (error.kind)` narrow. Agneta's own message is kept as `message`; `advice` says what to tell the user; `code` and `data` are the raw JSON-RPC values; and each kind has its structured data typed (`fields` and `reason` for `unenforceable`, `progress` for `engineDownloading`, `resetsAt` for `rateLimited`, …). Data is checked before codes (`needsSignIn`, `rateLimited`), then the code, then `-32602`'s data. Transport failures have kinds of their own: `notRunning` (nothing answered), `refused` (something answered but wouldn't upgrade: a browser's `Origin`, or not Agneta), `connectionClosed` (it was open and went) and `timeout`.

**Defaults.** The release port (47321), `build: "dev"` for 47331, or any `port` or `url`. No scope (app-only tools). Permission requests are declined unless the app answers them: a safe default, since `never-ask` sessions don't send them. `session/new`, `session/load` and `agneta/fork` wait out an engine download (`-32015`) for up to 10 minutes, reporting progress. Requests time out after 30 s, opening a session after 3 minutes, pairing after 310 s (past Agneta's 5-minute window), and prompts never (a policy's `maxSeconds` is the limit). A timeout rejects that call only.

**Getting and opening Agneta.** The protocol says: never open Agneta, or anything, without asking (docs/APP_PROTOCOL.md, Getting Agneta). So the client never opens anything by itself: `connect` takes a `guide`, a function that puts each question only the user may answer (get Agneta, open it, update it, connect a provider) to them and resolves to their answer, and an `onProgress` that hears every step in plain words. Without a guide it rejects with what it found, typed: `NotInstalledError`, `NotRunningError`, `OutdatedError`, `NetworkBlockedError`. A first version had a `launch` callback (ask, then open) and a 20 s wait; a user without Agneta was offered to open something they didn't have, and a first launch waiting on macOS's "downloaded from the Internet" question outlasted the 20 s. Decisions, each measured on macOS 26 (Intel) in November 2026:

- **An environment, passed in.** Finding Agneta needs the platform (LaunchServices), which the core mustn't import. `AgnetaEnvironment` is four small functions; `@agneta/client/node` has `nodeEnvironment()` (JavaScript for Automation through `osascript`, the only way to ask LaunchServices from Node without a native module: about 0.1 s, no Apple Events, so no Automation prompt) and `electronEnvironment({ app, shell })` (`app.getApplicationInfoForProtocol`, about a millisecond; Electron passed in, never imported). Spotlight was rejected: it also finds the copy in the Trash.
- **By URL scheme, then by bundle.** The scheme lookup tests exactly what the app will open; the bundle's identifier must be the build's (another app may claim `agneta://`), and its version is readable before opening. LaunchServices doesn't see a copy just put in `~/Applications` until it's opened (measured: not within 70 s), so both environments also look in the two Applications folders and open such a copy by its path.
- **Where it is, never the path.** `presence()` says `applications`, `elsewhere` or `onDiskImage`; the path (which holds the user's home folder name) stays inside the library.
- **A yes to getting Agneta covers opening it once installed,** within that flow: a second question at that moment is friction the rule wasn't written for. At launch (`pair: 'never'`) only the open question is asked, and only of someone with a kept token, as Project Chat did before.
- **Waits:** installing has no timeout (the user cancels); after opening, the port is polled every 250 ms for 5 s and then every second, with `slow` at 15 s and again at 60 s (`timeouts.slow`, `timeouts.keepWaiting`) and a 5-minute limit (`timeouts.open`), so an app that passes no signal doesn't wait forever on an Agneta that failed to start. Polling beats a notification: a refused loopback connect costs microseconds, and nothing else says "listening".
- **Versions:** `minimumVersion` against the bundle before opening and the catalog's `version` once connected; no `agneta/catalog` counts as 0.4.0, the last release without it; a development build's `0.0.0` and a bundle-less `dev` are never too old.
- **A disk image is a read-only volume under `/Volumes`,** as Agneta decides before offering to move: the environments check for `EROFS`, so an Agneta on a writable external drive is installed, and they look in the Applications folders when LaunchServices answers with a disk image's copy.
- **Cancelling cancels everything:** after the signal, nothing more is opened and a guide's late answer is ignored; the guide is raced against the signal so a cancelled connect never hangs on a question.
- **`EPERM` is `blocked`:** a sandboxed app without `com.apple.security.network.client` gets it from loopback (measured), which the old probe reported as "something refused the connection".
- **The install page** is `https://agneta.dahlbom.io/get/`, with only the Mac's architecture in the fragment (the browser never sends it): no query, nothing about the app or user. The architecture is the Mac's, from `sysctl.proc_translated` under Rosetta.

**Structured results.** Two layers again: `results` on opening, `result` on a prompt and `turn.structured` are the protocol, typed; `session.ask` and `client.ask` give a typed value or a typed error (`resultMissing`, `resultInvalid`). Decisions:

- **Agneta validates; the client only rejects further.** Agneta checks every call of its result tool with one validator, the same on every engine, and answers the model at once so it can correct the value within the turn; a client-side check would come after the turn, too late to help, and could disagree with what the model was told. So the client never decides validity: a value Agneta refused is `resultInvalid` (`source: 'agneta'`) whatever the app's schema says, and the app's own schema or `parse` may reject a value Agneta accepted (`source: 'client'`), for checks the JSON Schema subset can't say or for the app's types. An Agneta without `agneta/result` is `UnsupportedByAgnetaError` before anything is sent, never a fallback to parsing text.
- **Standard Schema without a dependency.** Zod 4.2+, ArkType and Valibot implement [Standard Schema](https://standardschema.dev) and its JSON Schema extension, so the client takes any of them through `~standard.jsonSchema.input({ target: 'draft-2020-12' })` (what the model must produce) and `~standard.validate` (the app's output type), with the spec's interfaces copied as types (`src/standard-schema.ts`, MIT). Plain JSON Schema is typed by a small `FromSchema` (objects, `required`, arrays, `enum`, `const`, primitives, `type` lists with `null`), deliberately small: anything richer is `unknown`, and an app wanting more uses a Standard Schema or its own type with `parse`. A `const` type parameter types an inline schema without `as const`.
- **Schemas declared when a session opens.** Engines take their MCP tools only when a session starts, and version 1 gives each declared schema a tool of its own, so a prompt can only ask for a schema the session declared. The client matches the schema passed to `ask` to a declared one (the same object, or equal JSON) and sends its name; any other is a `TypeError` before sending that says to declare it, rather than a request Agneta would refuse. `client.ask` is the one-shot: a session declaring `{ schema }`, one ask, closed.
- **Object roots.** Agneta needs `"type": "object"` at the root (an MCP tool's input is an object). Any other root is sent as `{ value: S }` (`required`, no other properties), with `$defs`, `definitions`, `$schema` and `$id` moved to the new root and local references pointed into `value`, and unwrapped when read, issues' paths too.
- **The result tool's calls aren't the model's work.** They arrive as ordinary tool calls tagged `_meta.agneta.result`; `toolCalls` leaves them out by default and `resultCalls` has them, while the event stream stays as Agneta sent it (`resultCallOf(update)` tells them apart).
- **A one-shot's turn by callback.** A `Turn` is thenable, so a promise can't hold one (it would resolve to the turn's result): `client.ask` gives the turn to `onTurn` once the prompt is sent, and its answer (`Answer`) has no `turn`.

**Reconnecting.** With `reconnect: true` (off by default), a dropped connection that had a remembered token reconnects quietly with backoff, never opening the approval window, and emits `reconnected`, or `accessRemoved` when Agneta no longer accepts the token. Sessions end with their connection (Agneta closes them), so open `Session`s end with `connectionClosed`; resuming is `client.loadSession(id)`, which the app decides.

## Tests

- **Unit tests** (`test/*.test.mjs`, `node --test`) run against a stand-in Agneta (`test/stand-in.mjs`): a small WebSocket server written for the tests, with frames of any size, server-initiated requests and scripted answers. They cover what a real Agneta can't be put into at will: every error code and its data, a download in progress, a queued turn, a rate limit, a user's Stop, an access change, a permission request, a refused upgrade, a reconnect. `install.test.mjs` puts a scripted environment in place of LaunchServices for every step of getting Agneta: not installed, on a disk image, an impostor, outdated, slow, declined, cancelled, and setup across a closed connection; `node.test.mjs` runs the real Node environment on macOS.
- **Type tests** (`test/types.test.ts`) compile with `tsc --noEmit`, so the discriminated unions keep narrowing, and `FromSchema`, Standard Schema inference and the `ask` overloads give the types they should.
- **Structured results** (`test/results.test.mjs`): the stand-in answers `agneta/result` by Agneta's rules (its declaration and ask parsing, refusals, `ResultTurn`'s outcome precedence, tagged updates, `valueOmitted`, an engine error carrying the report, an Agneta without the extension), with a small validator of its own; the integration test checks the same against the real validator through Goose's calls.
- **The integration test** (`test/agnetad.integration.mjs`) runs the library against the real headless host, `.build/debug/agnetad`, with Goose and the fake model (`agneta-fakes`), in a temporary `--home` on ports in 47800–47899 (the Swift tests use 474xx and 476xx, Replica Bench 479xx), stopping what it started by process group. It covers not running → open → connect, the catalog, pairing and the kept token, a rejected token, sessions with a policy and an MCP server, streaming, tool calls, cancel, steering, model options, a refusal with `unenforceable`, close, load, fork and traces live and read.
- **CI.** `.github/workflows/client-typescript.yml` builds, type-checks and unit-tests the package on Linux with Node 22 and 24 for every change to it; `ci.yml` runs the integration test on its macOS runners, where `agnetad` is built anyway, and Project Chat's tests on the library. `client-typescript-release.yml` publishes on a `client-typescript-v*` tag ([README](README.md#releasing)).

## Known gaps

- **No tool-server helper.** An app's MCP tools still need a Streamable HTTP server of their own (Project Chat's `project-tools.mjs` is about 120 lines). `httpMcpServer()` builds the registration, bearer and all; serving is the app's.
- **Browsers can't be supported** while Agneta refuses any `Origin`, which is deliberate.
- **No Swift client yet.** A Mac App Store app writes its own, following the protocol's Getting Agneta (every call it names works sandboxed); `clients/swift/` is planned separately.
- **No ad hoc schemas.** Agneta version 1 takes schemas only when a session opens; a schema per prompt needs Agneta's planned generic tool (the reserved name `any`), and `ask` would then send an undeclared schema instead of refusing it.
- **Sessions don't survive a reconnect.** That's Agneta's rule (a session belongs to its connection); the library makes the reload one call but doesn't do it unasked.
